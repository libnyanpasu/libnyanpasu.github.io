## 应用

### macOS 提示“Clash Nyanpasu 已损坏，无法打开”

这个提示通常不代表文件真的损坏，而是 macOS 的 Gatekeeper 拦截了没有经过 Apple 公证的应用。

#### 为什么会被拦截

按照 Apple 的政策，在 App Store 之外分发的应用，必须使用 Developer ID 证书签名并通过 Apple 公证，下载后才能直接打开。取得这张证书需要加入 Apple Developer Program：

- **年费**：每年 99 美元，停止续费后无法再签发新的安装包。
- **身份**：必须以个人的真实法律身份，或已注册的法人实体通过 Apple 的身份验证，证书上的开发者名称会随每个安装包公开。

Clash Nyanpasu 是由志愿者维护的开源项目，没有法人实体，也无法要求某位维护者以个人实名和年费为项目担保。因此官方安装包只带自签名（ad-hoc 签名），没有经过 Apple 公证。对这类应用，macOS 会在首次打开时显示“已损坏，无法打开”或“无法验证开发者”，必须由你手动放行后才能运行。

#### 如何放行

1. 确认安装包来自[官方发布页](https://github.com/libnyanpasu/clash-nyanpasu/releases)。如果怀疑下载不完整，请重新下载。
2. 将 Clash Nyanpasu 拖到“应用程序”目录后，在终端中清除隔离属性：

   ```bash
   xattr -dr com.apple.quarantine "/Applications/Clash Nyanpasu.app"
   ```

3. 也可以不使用终端：先尝试打开一次应用，再前往**系统设置 → 隐私与安全性**，对该应用选择**仍要打开**。具体步骤请参阅 [Apple 的说明](https://support.apple.com/zh-cn/102445)。如果该页面没有出现**仍要打开**按钮（提示“已损坏”时较常见），请使用上面的 `xattr` 命令。

通过浏览器重新下载安装包后，需要再次放行。

<Aside type="caution" title="只放行来源可信的安装包">
  放行意味着跳过 Gatekeeper 对这个应用的检查，请只对官方发布页下载的安装包执行。不要用 `sudo spctl
  --master-disable` 全局关闭 Gatekeeper，那会让所有应用都不再受检查。
</Aside>

#### 服务模式也可能被拦截

安装系统服务时，应用会把服务程序复制到应用包之外的目录，再交给 launchd 运行。这份副本同样没有 Developer ID 签名，放行应用本身并不会一并放行它，macOS 可能单独拦截。常见表现是服务已安装却无法启动，或**服务模式**回退为本地运行、TUN 无法开启。此时需要手动放行服务程序：

- 前往**系统设置 → 隐私与安全性**，如果出现服务程序被阻止的提示，选择**仍要允许**。
- 前往**系统设置 → 通用 → 登录项与扩展**，确认 Clash Nyanpasu 相关的后台项目没有被关闭。
- 如果仍被拦截，对被拦截的服务程序清除隔离属性，路径以系统提示中显示的为准：

  ```bash
  sudo xattr -dr com.apple.quarantine "<服务程序路径>"
  ```

完成后回到**设置 → 系统服务**重新启动服务。服务模式的完整流程请参阅[系统代理与 TUN](../../tutorial/system-proxy-tun)。

如果放行后问题仍然存在，请在 [GitHub 问题](https://github.com/libnyanpasu/clash-nyanpasu/issues/new/choose)中提供具体的 macOS 版本、应用版本和完整的提示内容。

### 配置目录和日志目录在哪里？

打开**设置**，使用配置目录或数据目录旁的文件夹按钮。托盘菜单也有打开目录的快捷入口。日志保存在数据目录下的 `logs` 文件夹。若应用无法打开，可在文件管理器中输入下面对应系统的路径。

#### 默认目录路径

- Windows：配置目录为 `%APPDATA%/Clash Nyanpasu/config`，数据目录为 `%LOCALAPPDATA%/Clash Nyanpasu/data`。
- macOS：`~/Library/Application Support/Clash Nyanpasu`。
- Linux：配置目录为 `$XDG_CONFIG_HOME/clash-nyanpasu` 或 `$HOME/.config/clash-nyanpasu`；数据目录为 `$XDG_DATA_HOME/clash-nyanpasu` 或 `$HOME/.local/share/clash-nyanpasu`。

从 v1.6.0 开始，配置和数据分别存放，日志目录位于数据目录内。Windows 用户可以自定义或迁移配置目录。若设置了自定义目录，以自定义路径为准。

Windows 便携版会将配置目录和数据目录放在可执行文件旁的 `.config/clash-nyanpasu` 与 `.data/clash-nyanpasu`。不同安装包的说明请参阅[安装指南](../../tutorial/install)。

### 如何修改应用日志等级？

打开**设置 → Nyanpasu 设置**，修改**应用程序日志级别**，保存后立即生效。可选等级为 `trace`、`debug`、`info`、`warn`、`error` 和 `silent`（不输出应用日志）。

旧版指南中直接修改 `nyanpasu-config.yaml` 的方法针对的是旧设置文件；当前版本请在设置中修改日志级别。

### 如何开启 TUN？

请参阅[系统代理与 TUN](../../tutorial/system-proxy-tun)。操作步骤取决于操作系统和安装包。不要把 1.x 的手动权限命令用于 2.0 安装。

### 为什么订阅没有返回可用节点？

部分服务商会根据请求的 User-Agent 决定返回内容。Clash Nyanpasu 默认发送 `clash-nyanpasu/v{version}`，其中 `{version}` 是应用版本。请询问服务商是否支持此值，或将配置的**用户代理**改成服务商认可的值，例如 `clash-meta`。添加订阅时可以设置，也可以在配置的更新选项中修改。不要在公开问题中分享完整订阅链接。

### 应用目录和内核目录是什么？

应用目录（内核目录）包含应用自带的资源和内核文件，可从托盘菜单或**设置**打开。请通过**设置 → 系统服务**安装和管理系统服务，不要手动安装服务二进制文件。大多数用户不需要直接修改应用目录中的文件。

## 使用应用

### 应该选择哪种模式？

建议先使用[系统代理和规则模式](../../tutorial/system-proxy-tun)。如果需要接管不遵循操作系统代理设置的应用，可以考虑 TUN，并先了解对应的平台权限要求。

### 如何选择或更新内核？

打开**设置 → Clash 设置**，使用**核心管理**。可选内核和兼容性说明请参阅[选择和管理内核](../../tutorial/cores-and-compatibility)。

### 应该从哪里开始？

先查看[配置与订阅](../../tutorial/profiles-and-subscriptions)导入或更新配置，再阅读[仪表盘与流量分析](../../tutorial/dashboard-and-traffic)了解运行数据。
